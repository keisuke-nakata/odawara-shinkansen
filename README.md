# 小田原⇔東京 新幹線時刻表

指定日の小田原⇔東京の東海道新幹線のうち、**小田原に停車する列車（こだま・一部のひかり）だけ**を、
往路・復路並べて表示する。各列車に「カレンダーに登録」リンクが付いている。

```
node cli.js 水             # 次の水曜日（今日を含む）を開く
node cli.js 10/7           # 日付で指定（YYYY-MM-DD も可）。省略すると今日
node cli.js 10/7 --text    # ターミナルに表示
node cli.js 10/7 --json    # JSON で出力
npm test
```

既定では手元で Web サーバー（http://127.0.0.1:8741 、自分の PC からだけ開ける）を起動して、
ブラウザで開く。終了するには Ctrl+C。

- 画面上の「前日」「翌日」、日付の入力欄、← → キーで日付を移動できる（今日から1ヶ月先まで）
- サーバーが動いている間にもう一度実行すると、そのサーバーで指定日を開くだけになる
- `--no-open` でブラウザを開かない、`--port` で別のポート番号を使う

Node.js 18 以降（fetch と EUC-JP の TextDecoder を使う）。外部パッケージは不要。

## スマホ・外出先から見る（GitHub Pages）

毎日 GitHub Actions で、今日から31日先までの日付ごとのページ（`site/`）を作り直し、
GitHub Pages に公開する（`.github/workflows/pages.yml`）。スマホからは公開 URL を開くだけ。

- 置くのは作り終えた HTML だけなので、アクセスが多くても公式サイトへの問い合わせは増えない。
  公式サイトに問い合わせるのは毎日1回（4:17 頃）のページ作成のときだけ
- GitHub Pages と、公開リポジトリの GitHub Actions は無料で、アクセス数による課金はない
- 1日でも取得に失敗したら公開せず、前回のページが残る（GitHub から失敗の通知メールが届く）
- 検索エンジンに載らないよう、各ページに noindex を付けている
- カレンダーの登録先アカウントはページに書かない。ページ下の入力欄に入れると、そのブラウザが覚えておく
- 公開リポジトリの定期実行は60日間動きがないと GitHub に止められるので、毎回有効にし直している

手元で作って確かめるには `npm run build:site`（`site/` に書き出す）。

## カレンダーへの登録

「カレンダーに登録」を押すと、件名・時刻・場所が入った状態で Google カレンダーの予定作成画面が開く。
「保存」を押すと登録される。

- 件名: `🚄 08:03→08:36 こだま916号`
- 時刻: 乗車駅の発車〜降車駅の到着
- 場所: 乗車駅（小田原駅／東京駅）

手元のサーバー（`node cli.js`）では、登録先のアカウントを `config.json` の `calendarAccount`
（または `--account`）で指定する（`config.example.json` を写して作る。公開しないよう .gitignore 済み）。
ブラウザで複数の Google アカウントにログインしていても、このアカウントで開く。
公開ページでは、ページ下の入力欄で指定する。
件名などの書式は `src/calendar.js` で変えられる。

## 仕組み

| 取りたいもの | 取得元（JR東海公式サイト） | リクエスト数 |
| --- | --- | --- |
| 列車一覧・小田原発 | 小田原駅の「各駅の時刻表」（上り・下り） | 1日あたり2回 |
| 東京着（往路） | 経路検索（小田原発の時刻で「出発」検索） | 列車ごとに1回、初回のみ |
| 東京発・小田原着（復路） | 経路検索（小田原発の時刻で「到着」検索） | 列車ごとに1回、初回のみ |

- 駅の時刻表は日付ごとの内容になっている。土休日は平日のみ運転の列車が消え、臨時列車には ◆ が付く。
- 経路検索は種別（こだま／ひかり）を1つに絞って問い合わせる。追い越す列車が返ってくるのを防ぐため。
- 経路検索の結果は `.cache/arrivals.json` に保存する（キー: 方向・列車名・小田原発時刻。60日で取り直す）。
  初回は約90本を1秒間隔で問い合わせるので約2分かかる。2回目以降は2リクエストで終わる。
- 復路で東京からの経路が見つからない列車（例: 小田原始発のひかり733号）は一覧から除く。

## 注意

- 公開 API ではなく Web ページを読み取っている。ページの形式が変わったら、黙って取りこぼさずに
  エラーで止まるようにしてある（列車名の数と読み取れた列車の数を突き合わせている）。
- 公式サイトは任意の日付を表示するが、画面上で選べるのは当日から約1ヶ月先まで。
  それより先の日付は、臨時列車やダイヤ改正が反映されていない可能性があるので警告を出す。

## 構成

- `src/jrc.js` — 時刻表の取得と解析。通信・キャッシュ・待機は外から渡す
- `src/calendar.js` — Google カレンダーの予定作成 URL
- `src/page.js` — 表示する HTML（日付の移動を含む）
- `src/server.js` — 手元で動かす Web サーバー
- `src/dates.js` — 日付の指定（10/7・水 など）の解釈
- `cli.js` — 手元で使うコマンド（サーバーの起動・テキスト表示）
- `src/node-io.js` — Node での通信・キャッシュ（cli.js と build-site.js で共通）
- `scripts/build-site.js` — 公開用の静的ページを `site/` に作る
- `.github/workflows/pages.yml` — 毎日ページを作り直して GitHub Pages に公開する
- `test/` — 公式サイトの応答（時刻表の部分だけ）を固定データにしたテスト
